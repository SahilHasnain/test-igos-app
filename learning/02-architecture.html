Architecture & Design Patterns

How the codebase is structured and why.

Layer Cake Architecture

① UI — React Components (app/*.tsx)
▼ fetches data via API calls
② API Routes — Next.js Server (app/api/*.ts)
▼ calls services with request context
③ Application Services — Business orchestration (src/services/*.ts)
▼ uses domain logic + repository calls
④ Domain Logic — Pure rules, no DB (src/domain/*.ts)
▼ operates on typed interfaces
⑤ Repository Interfaces — Contracts (src/repositories/*.ts)
▼ implemented by either demo OR appwrite
⑥a Demo — In-Memory Arrays
⑥b Appwrite — Real Database

Repository Pattern — The Key Idea

Services never talk to the database directly. They use an interface. Two implementations exist: Demo (arrays) and Appwrite (real DB).

Interface

src/repositories/matter-repository.ts
interface MatterRepository {
  create(input): Promise<Matter>
  findById(scope, id): Promise<Matter|null>
  list(query): Promise<Matter[]>
  update(scope, id, ver, patch)
}

Runtime Switching

The file src/services/runtime.ts decides which implementation to use at runtime.

// src/services/runtime.ts

function createRuntimeMatterService() {
  return dataMode() === "demo"
    ? new MatterService(demoMatters, auditService)     ← demo mode
    : createAppwriteMatterService();                   ← appwrite mode
}

function dataMode() {
  return readServerEnvironment().IGOS_DATA_MODE;  ← "demo" or "appwrite"
}

⚠ The SAME pattern is repeated for governance, assurance, advanced governance, supplier, and workflow services.

Appwrite Service Factory

src/appwrite/services.ts creates all Appwrite repositories, wires them into services, and returns them.

// src/appwrite/services.ts

export function createMatterService() {
  const env = getEnv();
  const admin = getAdmin();

  const matters = new AppwriteMatterRepository(
      admin.databases, env.APPWRITE_DATABASE_ID, env.APPWRITE_CASES_TABLE_ID
  );

  const audit = new AppwriteAuditRepository(...);

  return new MatterService(matters, new AuditService(audit));
}

This file already imports all 25+ Appwrite repositories. The adapters exist — they just need to be wired into the runtime and tested.

API Routes — How the Backend Works

// app/api/matters/route.ts

export async function GET(request: Request) {
  // 1. Get query params
  const matId = url.searchParams.get("matId");

  // 2. Resolve user context (demo or appwrite auth)
  const context = await resolveRuntimeContext(request, matId);

  // 3. Get service (demo or appwrite)
  const service = createRuntimeMatterService();

  // 4. Call service (handles auth + domain logic)
  const matters = await service.list(context, { matId });

  return NextResponse.json({ matters });
}
