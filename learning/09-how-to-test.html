Level 2 — Manual Browser Test (Demo Mode)

Setup:

npm run dev

Opens login page at localhost:3000/login

Select a demo role and click "Enter workspace"

What you see at login:

  • ☐ Blue banner: "Demo mode — records stay in this browser session"
  • ☐ Role dropdown with 6 options (DPO, MAT admin, etc.)
  • ☐ "Enter workspace" button (no email/password needed)

Click-through checklist — every view:

Sidebar Navigation

☐ Overview — metric cards, priority matters table, health bars, workload donut, activity timeline
☐ SARs — filterable matter register with 7 demo cases
☐ FOI — same register, filtered to FOI type
☐ Breaches — same register, filtered to Breach type
☐ DPIAs — DPIA progress panel with sections + risks
☐ ROPA — processing activities table with CRUD
☐ Policies — policy cards with lifecycle transitions
☐ Redaction — workspace with analysis, suggestions, manifests
☐ AI — AI system register with risk levels
☐ Assets — information asset register
☐ Records — retention rules, holds, disposal
☐ Contracts — contract governance with IG terms
☐ Assurance — programme overview, actions, findings
☐ Risks — risk register with severity ratings
☐ Audits — audit programme with status tracking

Interactions

☐ Search box filters matters by reference/title/academy
☐ Academy dropdown filters to specific academy
☐ "＋ New matter" button opens create form
☐ Create form: select type, enter title, pick academy, submit
☐ Clicking a matter row opens detail drawer

Demo mode notes:
  • Data lives in browser memory — refreshing the page resets to initial demo matters
  • Role enforcement is UI-only (hides buttons). Real enforcement happens server-side in Appwrite mode
  • The "Placeholder environment" banner appears to remind you
  • Each view renders via API fetches from /api/* routes (they use demo repositories in demo mode)

Quick smoke test (5 minutes):

  1. Run npm run dev, go to localhost:3000
  2. Select DPO role, click Enter workspace
  3. Verify Overview loads with metric cards and tables
  4. Click SARs → see register → click a row → drawer opens
  5. Click ＋ New matter → fill form → submit → verify it appears
  6. Click through every sidebar view (SARs through Audits) — each should render without errors
  7. Click ROPA → click "Add activity" → fill form → submit
  8. Click Policies → verify policy cards render
  9. Click AI → verify AI systems table renders
  10. Click Assurance → verify programme panel renders
  11. Use search box → type "SAR-2026" → verify filter works
  12. Change academy dropdown → verify filter works
  13. Click ↩ sign-out → verify returns to login page
  14. Select Auditor role → verify "＋ New matter" button is hidden
  15. Select Read only role → verify fewer nav items visible

Level 3 — Full Integration (Appwrite Mode)

Prerequisites:

  • Appwrite project created (Cloud or self-hosted)
  • Run npm run provision — creates database + 33 tables + bucket
  • Run npm run seed — creates MAT, 5 academies, admin user
  • Copy all IDs from seed output into .env.local
  • API key with database/storage/user scopes
Start in Appwrite mode:
  npm run dev

Login:
  Go to localhost:3000/login
  Enter the admin email and password from seed script
  Click "Sign in"

Acceptance Checks (from docs/dev-handover.md):

Auth & Tenancy:
  ☐ DPO and MAT admin can see Federation-wide records
  ☐ Academy lead sees ONLY assigned academy records
  ☐ Auditor cannot create or advance a matter
  ☐ Read-only user cannot mutate data
  ☐ Cross-MAT reads and writes fail

Workflows & Deadlines:
  ☐ SAR month-end deadlines clamp correctly (31 Jan → 28 Feb)
  ☐ Breach deadlines cannot be paused
  ☐ SAR extensions require approval record, max +2 months
  ☐ FOI clarification pauses record start/resumption/rationale

Audit & Documents:
  ☐ Audit events link to preceding event (hash chain)
  ☐ Document upload stores file + checksum metadata
  ☐ Failed metadata write removes the uploaded file
  ☐ Duplicate notification idempotency keys = one send

Infrastructure:
  ☐ /api/health returns OK without secrets
  ☐ Microsoft 365 disabled does NOT affect login/cases/docs
  ☐ Backup restoration tested in non-production environment

CI Pipeline (What GitHub Runs Automatically)

File: .github/workflows/ci.yml — runs on every push and PR.

Step 1: npm ci --ignore-scripts       ← clean install
Step 2: npm audit --audit-level=high   ← security gate (fails on high vulns)
Step 3: npm run typecheck              ← tsc --noEmit (TypeScript errors)
Step 4: npm test                       ← all 20 test files (121 tests)
Step 5: npm run build                  ← production build (catches import errors)

ALL 5 steps must pass for CI to be green.
