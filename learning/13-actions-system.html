Actions — Cross-Module Tracking

Actions are remediation tasks generated from findings, risks, DPIAs, and policies. They track what needs to be done, who owns it, and whether it's complete.

What is an Action?

An Action is a tracked remediation task that says: "Someone must do this thing by this date."

It is the output of the assurance and governance process. When you identify a gap — a finding, a risk, a policy exception — you raise an action to track its resolution.

Action Fields

idACT-123456 — unique reference
titleWhat needs to be done
descriptionFull explanation
ownerUserIdWho is responsible
prioritylow / medium / high / critical
statusopen / in-progress / blocked / awaiting-evidence / complete / cancelled
dueAtDeadline date
sourceTypeWhere it came from (see below)
sourceIdLink back to the originating record
evidenceDocumentIdsProof of completion (required to close)

Lifecycle

1
Created — Action is raised from a source (finding, risk, manual entry)
2
In Progress — Owner is working on it
3
Awaiting Evidence — Work done, waiting for proof
4
Complete — Evidence attached, rationale recorded, action closed

Where Actions Come From (sourceType)

audit-finding

An audit identified a gap. E.g. "Encryption at rest not configured" → action to fix it.

Created from: Audit Findings panel

risk-treatment

A risk treatment plan says "we'll do X by Y date" → that's an action.

Created from: Risk Register (treatments field)

incident

A data breach or security incident requires follow-up actions.

Created from: Breach workflow

dpia

DPIA identified mitigations that need implementing → tracked as actions.

Created from: DPIA risk register

policy

A policy exception or non-compliance triggers a remediation action.

Created from: Policy exceptions

manual

DPO or MAT admin creates an action directly — e.g. "Schedule annual IG review".

Created from: Actions panel "New action" button

Current State in IGOS

What works

  • Assurance Actions API — create, list, save
  • Actions panel in sidebar — fetches from API, shows list
  • Assurance Overview — shows priority actions with complete button
  • Appwrite persistence — actions survive page refresh

What's incomplete

  • No "New action" button — manual creation UI not built (domain model supports sourceType: "manual")
  • Complete button needs evidence docs (not wired to storage)
  • Actions don't show in individual matter detail drawer
  • No filtering by priority, status, or owner
