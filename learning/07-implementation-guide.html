Implementation Guide — What To Do

Step-by-step breakdown of the remaining work.

PHASE 1

Provision Appwrite Dev Project

Step 1

Create Appwrite Project

Go to Appwrite Cloud or self-hosted. Create a project named "igos-dev".

Step 2

Create Database + Tables from schema.json

Use infra/appwrite/schema.json to create: database "igos-core", all 33 tables, all columns, all indexes, the "case-documents" bucket.

Step 3

Create API Key

Least-privilege key with database, table-row, storage, user scopes. Store in secrets.

Step 4

Seed First MAT + User

Create user → MAT → academies → membership with mat-admin + dpo roles.

Step 5

Configure .env.local

Set all APPWRITE_* variables + IGOS_DATA_MODE=appwrite.

PHASE 2

Wire Appwrite in Runtime

The Appwrite adapters are already written in src/appwrite/. The runtime switcher in src/services/runtime.ts already routes to them for matter, audit, and workflow. But some services still throw errors in Appwrite mode.

Check each function in runtime.ts:

createRuntimeMatterService() → ✅ Works

createRuntimeWorkflowService() → ⚠ Verify

createRuntimeGovernanceServices() → ⚠ Verify

createRuntimeAssuranceServices() → ⚠ Verify

createRuntimeAdvancedGovernanceServices() → ⚠ Verify

createRuntimeSupplierService() → ⚠ Verify

⚠ Every Appwrite adapter in src/appwrite/services.ts already imports all 25+ repositories. Verify they instantiate correctly.

PHASE 3

Connect UI to API

The biggest gap: the UI (app/igos-client.tsx) is entirely client-side. It uses useState with hardcoded data from src/demo/ui-data.ts.

Current (Demo)

useState(initialMatters)  ← hardcoded
setMatters(items => ...)   ← local state
role selector → fake      ← no auth
academy filter → fake     ← no isolation

Target (Appwrite)

fetch("/api/matters?matId=X")  ← real API
POST("/api/matters", {...})     ← server-side
role from JWT membership       ← real auth
academy from JWT membership    ← real isolation
PHASE 4

Authentication UI

No login page exists. The browser needs Appwrite account SDK to:

  • Create session (email + password)
  • Create JWT for API calls
  • Send JWT in Authorization header
  • Handle token refresh
PHASE 5

Deploy & Test

Deploy

  • Create Dockerfile or use Coolify
  • Set environment variables
  • Deploy to dev environment

Acceptance Checks

  • MAT admin can list/create matters
  • Academy-scoped user sees only their data
  • Cross-MAT access is blocked
  • Workflow creates audit event
  • Document upload stores file + checksum
  • Failed metadata write removes uploaded file
  • Deadlines use Europe/London calendar
  • /api/health returns OK
PHASE 6

Background Jobs & Extras

  • • Set up cron/worker for deadline-scan.ts (SAR deadline alerts)
  • • Set up cron/worker for governance-reminders.ts (policy review reminders)
  • • Replace DemoNotificationAdapter with real email/Teams adapter
  • • Configure Appwrite Storage + antivirus scanning
  • • Implement disposal processing for expired records
  • • Complete backup and restoration testing
